InfoDeck — v1.6 · D3 design

Two bugs. 1) In WhatsApp you got the file names as text and no files — two mistakes stacked, both mine, both named below. The fix sends the files for real, using the one pattern that works in every app: text first, files as a follow-up send. 2) “Shared from InfoDeck” becomes a switch, off by default.

DESIGN ONLY · nothing built · no version bump Reply by tag: “S2.2 → default on”, “Q3 → b”, or “defaults” = all recommended This supersedes part of B4 — files come back into the picker, but never into the text
Checked in the shipped source. The text builder in 1.6 lists Kind.FILE in its output order, so a ticked file was written into the message as Policy document.pdf: Policy document.pdf. At the same time the attachment intent used a wildcard type and silently fell back to text-only. Result: WhatsApp received a message containing file names, and nothing else. Both are fixed here; the first is a one-line removal, the second needs the flow in S3.
