InfoDeck — v1.1 · D2 design

Correction round. The five fixed text-size stops from D1 are dropped and replaced with a continuous, live, per-role sizing system that also scales the layout, not just the letters. Plus the two new variables you asked for: file attachments (PDF / DOCX) and tags. Mock date Tue 18-Aug-2026.

What was wrong with D1: five hard-coded stops (0.90 / 1.00 / 1.15 / 1.30 / 1.45), text-only scaling, a modal sheet you had to Apply, and rows that stayed the same height so big text looked cramped. None of that is flexible. This round: any size from 70 % to 200 % in 1 % steps, applied live as you drag, layout metrics scaling with it, six per-role fine-tuners, pinch-to-zoom on the Home list, and an honest read-out of what your phone’s own font setting is doing on top.

#RuleDetail
1One source of truthtextScale (0.70–2.00) lives in settings; slider, steppers, presets and pinch all write the same number
2Layout follows, dampedlayoutScale = 1 + (textScale − 1) × 0.6, clamped 0.80–1.60 — the UI grows with the text without wasting the screen
3Per-role resultfinal sp = base sp × textScale × (1 + roleOffset), clamped 8–46 sp
4Floors and ceilingsIcons 18–40 dp · buttons ≥ 44 dp · tap targets never below 44 dp — accessibility floor holds at 70 %
5UntouchedSheet clearance stays max(25 % height, nav bar + 24 dp); notification text belongs to Android, not to us
6PerformancePinch updates a single state value; the list recomposes, nothing is re-measured off-screen. Persisted on release, not on every frame

C4 · Database — schema 1 → 2, additive

#ChangeDetail
1New table tagsid, name (unique, case-insensitive), createdAt, lastUsedAt
2New table card_tagscardId + tagId, both indexed, cascade on card delete
3New table filesid, cardId, displayName, storedName, mime, sizeBytes, addedAt, order — cascade on card delete
4MigrationA real 1→2 migration, not a wipe. Three CREATE TABLEs and their indexes; no existing table is touched, so every card, date and scheduler survives untouched. Tested by opening a v1 database, migrating, and asserting the row counts match
5Backup formatVersion 2. A v1 backup still restores; a v2 backup restored on an older build ignores what it doesn’t know
