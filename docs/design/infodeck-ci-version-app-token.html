InfoDeck · Automatic PR versioning without workflow approval prompts

CI design, 15-Oct-2026. No Android UI or app data changes.

Before

PR opened by owner
Prepare builds and uses GITHUB_TOKEN to push VERSION
Next PR workflow requires manual approval under GitHub's bot-triggered approval policy.

After

PR opened by owner
Prepare compares computed version with branch VERSION
If different, create repository-scoped GitHub App token; push VERSION
New PR workflow runs normally; no GITHUB_TOKEN-initiated approval banner

Security boundaries

  1. Fork PR: never receive the GitHub App token or automated version push.
  2. Unchanged VERSION: no App token and no push.
  3. Missing App configuration: clear CI error; do not silently fall back to GITHUB_TOKEN.
  4. The App has Contents: Write on InfoDeck only, stored as encrypted repository secret and a public Client ID variable.
  5. Approval policies for outside contributors remain enabled. This does not auto-approve any untrusted workflow.

Review checklist

1. CI-only release:none PR passes without credentials when VERSION is unchanged. 2. Owner installs the dedicated GitHub App. 3. Next feature PR automatically receives a VERSION commit and an unblocked PR workflow. 4. Signed APK and artifact checks remain unchanged.
